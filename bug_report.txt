Here is a concise bug report from reading the Python code paths (tests were not run: pytest/pip are not available in this environment).
Critical / high impact
1. Belote “cut” detection never works (method vs string)
cut compares the bound method get_suit_name to the trump string, so it is always false. Trump follow / surcoupe style branches that depend on cut are wrong.
belote.py
Lines 298-301
Should call winning_card.get_suit_name() == self.trump_suit.
2. play_card advances the turn even when the card was not in hand
If no card matches card_value, the loop does nothing, but execution still reaches the else branch and sets active_player = self.next_player(player), so the game state can desynchronize from the round.
game.py
Lines 369-390
You likely want to return None (or raise) immediately when no card matched, without changing active_player.
3. Login flow can raise KeyError on successful login
After login_user, the code reads session['username'], but this handler never sets session['username'] (that is only done in the game-specific start routes).
common_routes.py
Lines 61-70
With debug logging enabled, successful login can crash here.
4. Socket on_join can raise KeyError if game_id is missing from the session
Direct indexing on session['game_id'].
common_routes.py
Lines 344-349
Use session.get('game_id') (and align with the game_id argument) so a partial session does not kill the handler.
5. next_player can recurse forever if every seat is inactive
If get_playing_players() is empty (or the invariant breaks), this never finds an ACTIVE player.
game.py
Lines 410-421
Worth guarding (e.g. cap iterations or assert at least one active player).
Medium / correctness & packaging
6. Round.card_played return value is wrong
cards_played is initialized with one entry per player, so len(self.cards_played) always equals len(self.players) and the return is always 0. Misleading if anything ever uses the return value.
round.py
Lines 22-30
7. populate_from_state mixes state and state_copy for trump card
Most of the method uses state_copy, but trump restoration uses the original state object.
game.py
Lines 164-166
For consistency and future refactors, use state_copy here.
8. Missing dependency: flask_cors is imported but not listed in requirements.txt
__init__.py
Lines 19-19
Installs from requirements.txt alone can fail unless Flask-Cors is added.
9. Deck silently drops cards when deck_size % 4 != 0
Comment admits the remainder is ignored; wrong deck size yields fewer than deck_size cards.
deck.py
Lines 10-18
10. player_played_process assumes the player exists
If get_player_by_name returns None, play_card and later logic will blow up.
common_routes.py
Lines 237-241
Lower severity / hygiene
11. emit_to_players can mutate the caller’s data dict
When data is a dict, data2 = data aliases the same object, then keys like game_id / state are added in place.
common_routes.py
Lines 421-426
Copy first (data2 = dict(data)) if callers reuse the same dict.
12. GameState.make_serializable calls convert_dict_to_string(self.bets) twice (harmless duplicate work).
game_state.py
Lines 56-59
  self.convert_dict_to_string(self.bets)
  self.convert_dict_to_string(self.hand_points)
  self.convert_dict_to_string(self.scores)
  self.convert_dict_to_string(self.bets)
13. Card.card_from_value does not guard None or too-short strings; callers must guarantee shape "s7" etc., or you get TypeError / odd int('') failures.
The single clearest game-rule bug in the above is (1) missing () on get_suit_name. The single clearest state machine bug is (2) advancing the turn when the card was not removed. I can propose concrete patches for these two first if you want them fixed in-repo.
